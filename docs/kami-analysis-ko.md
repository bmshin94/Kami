# Kami 분석 정리 (한국어)

Kami 저장소를 직접 뜯어보고 정리한 문서. 프로젝트의 정체, 설치·사용법, 기술 구조,
라이선스 제약, 그리고 이를 활용한 수익화 전략까지 한 번에 정리했다.

## 1. 이게 뭐야?

**Kami(紙, かみ = 일본어로 '종이')** 는 AI 에이전트에게 문서 디자인 능력을 부여하는
오픈소스 스킬 패키지다.

> 핵심 철학: **"Good content deserves good paper"** — 좋은 내용은 좋은 종이를 받을 자격이 있다.

### 해결하는 문제

| | 결과 |
|---|---|
| 평소 AI | 내용은 괜찮지만 밋밋함. 세션마다 스타일이 제각각 |
| Kami 설치 후 | 편집디자인급 PDF. 언제 요청해도 동일한 톤 유지 |

비유하자면 **예쁜 빵틀 세트 + 레시피북**이다. 반죽(내용)만 넣으면 모양이 예쁘게 나온다.

### 만들 수 있는 문서 9종

| 문서 | 용도 | 한국어 템플릿 |
|---|---|---|
| Resume | 이력서 / CV | `resume-ko.html` |
| One-Pager | 1장짜리 요약본, 사업 개요 | `one-pager-ko.html` |
| Long Doc | 백서, 기술보고서 (6~15p) | `long-doc-ko.html` |
| Letter | 공식 레터, 추천서, 사직서 | `letter-ko.html` |
| Portfolio | 작품집 / 케이스 스터디 | `portfolio-ko.html` |
| Slides | 발표 자료 (PDF 기본, PPTX 가능) | `slides-weasy-ko.html` |
| Equity Report | 주식 리포트 / 투자 메모 | `equity-report-ko.html` |
| Changelog | 릴리스 노트 | `changelog-ko.html` |
| Landing Page | 제품 랜딩페이지 (배포 가능) | `landing-page-ko.html` |

한국어 템플릿 9종이 모두 존재한다. 다이어그램은 인라인 SVG 18종을 제공한다.

### 디자인 기조

- 배경: 따뜻한 종이색 `#f5f4ed`
- 강조색: 잉크 블루 `#1B365D`
- 서체: 언어별 세리프 1종 (한국어 = Source Han Serif K)

## 3. 설치 및 사용법

### 3-1. 스킬 설치 (3가지 중 택1)

**① 한 줄 설치 (추천)**

```bash
npx skills add tw93/kami -a claude-code codex cursor -g -y
```

`~/.agents/skills/` 에 한 벌 설치되고 Claude Code · Codex · Cursor가 공유한다.
업데이트는 `npx skills update -g -y`.

**② 플러그인 설치** (Claude Code v2.1.142 이상)

```bash
/plugin marketplace add tw93/kami
/plugin install kami@kami
```

`/kami:kami` 로 네임스페이스가 붙는다. 호스트가 업데이트를 관리한다.

**③ Claude Desktop**

릴리스 애셋 `kami.zip` 다운로드 → Customize > Skills > "+" > Create skill 에 업로드.

> GitHub의 "Source code zip"이 아니라 **릴리스 애셋 `kami.zip`** 이어야 한다. 구조가 다르다.

### 3-2. 렌더링 엔진 설치 (필수)

스킬만 깔면 "설계도"만 있는 상태다. 실제로 PDF를 굽는 엔진은 별도로 설치한다.

```bash
pip install weasyprint pypdf pymupdf python-pptx pygments

# Linux
sudo apt-get install -y libcairo2 libpango-1.0-0 libpangoft2-1.0-0 libharfbuzz0b
# macOS
brew install cairo pango gdk-pixbuf libffi
```

| 패키지 | 없으면 |
|---|---|
| `weasyprint` + `pypdf` | **PDF 자체가 안 나옴 (필수)** |
| `pymupdf` | 검증 / 스크린샷 불가 |
| `python-pptx` | PPTX 출력 불가 (PDF는 정상) |
| `pygments` | 코드블록 흑백 처리 |

설치 확인:

```bash
python3 skills/kami/scripts/build.py --doctor
```

### 3-3. 사용

슬래시 커맨드가 필요 없다. 자연어로 요청하면 자동 발동한다.

```
"스타트업 원페이저를 만들어줘"
"이력서를 만들어줘"
"발표용 슬라이드를 만들어줘"
"이 리서치를 장문 문서로 정리해줘"
"앱 랜딩 페이지를 만들어줘"
```

**브랜드 프로필 (선택)**: `~/.config/kami/brand.md` 에 이름·이메일·브랜드컬러·말투를
적어두면 매번 알려주지 않아도 된다. 샘플은 `skills/kami/references/brand.example.md`.

우선순위: `명시적 지시 > 편집 판단 > 습관 노트 > frontmatter 기본값 > 내장 기본값`

## 4. 플러그인? 스킬? MCP? → 셋 다

3겹 구조로 포장되어 있다.

```
┌──────────────────────────────┐
│  ③ 플러그인 (배포 포장지)       │  plugins/, .claude-plugin/
│  ┌────────────────────────┐  │
│  │  ① 스킬 (본체 · 핵심)     │  │  skills/kami/SKILL.md
│  └────────────────────────┘  │
└──────────────────────────────┘
┌──────────────────────────────┐
│  ② MCP 서버 (선택 · 엔진 모드)  │  scripts/mcp_server.py
└──────────────────────────────┘
```

| 레이어 | 설명 |
|---|---|
| **① 스킬** | 본체. SKILL.md + 템플릿 + 레퍼런스. AI가 읽고 따라하는 설명서 |
| **② MCP 서버** | 선택형. 스킬 프롬프트를 로드하지 않고 "엔진"으로만 사용 |
| **③ 플러그인** | 포장지. `scripts/build_metadata.py` 가 스킬을 복사해 자동 생성 |

### MCP 서버가 노출하는 도구 5개

```bash
claude mcp add kami -- python3 <checkout>/skills/kami/scripts/mcp_server.py
```

| 도구 | 역할 |
|---|---|
| `kami_templates` | 템플릿 · 다이어그램 · 스키마 목록 조회 |
| `kami_doctor` | 렌더 / 검증 / 폰트 capability 진단 |
| `kami_render` | HTML → PDF 렌더 (WeasyPrint) |
| `kami_check` | 빈칸 · 수식 · 마크다운 잔여물 · 커버리지 검증 |
| `kami_screenshot` | PDF → 페이지별 PNG (시각 검수용) |

`mcp_server.py` 는 **외부 의존성 0개**로 구현되어 있다. 파이썬 표준 라이브러리만으로
stdin/stdout JSON-RPC를 직접 처리한다.

## 5. API 토큰이 필요한가? → 불필요

코드 전체를 검색한 결과 **API 키 관련 코드가 한 줄도 없다.**
(`token` 이라는 단어는 전부 "디자인 토큰 = 색상 변수" 의미였다.)

Kami는 AI가 아니라 **AI가 읽는 문서 + 파이썬 스크립트**다. 이미 사용 중인
Claude / Codex가 두뇌 역할을 하고, Kami는 손발만 제공한다.

### 네트워크를 쓰는 곳은 2군데뿐

| 스크립트 | 목적 | 성격 |
|---|---|---|
| `check-update.sh` | GitHub 릴리스 버전 확인 | 하루 1회, 3초 타임아웃, 실패 시 무시. 문서 내용 전송 없음 |
| `ensure-fonts.sh` | CJK 폰트 다운로드 | jsDelivr CDN / tsanger.cn 에서 폰트 파일만 |

폰트를 미리 설치해두면 **오프라인에서도 완전히 동작**한다.

## 7. 로컬 에이전트 구축에 참고할 설계 패턴

소스코드보다 **설계 철학**이 훨씬 값지다. 배울 점 5가지.

### ① Progressive Disclosure (점진적 공개) — 가장 중요

```
SKILL.md (491줄)          ← 항상 로드. 판단 로직만
  ↓ 필요할 때만
references/design.md      (1,460줄)
references/diagrams.md    (679줄)
references/writing.md     (561줄)
```

SKILL.md 원문: *"read the lowest tier that covers the task, not all of it"*

5,200줄을 전부 로드하면 컨텍스트가 폭발한다. "목차"만 항상 올리고 본문은 필요할 때만
연다. 에이전트 설계에 그대로 적용 가능한 패턴.

### ② 결정론적 검증 루프

AI의 자기 판단 대신 **파이썬 스크립트가 기계적으로 채점**한다.

| 검사 | 잡아내는 것 |
|---|---|
| `check_placeholders` | `{{빈칸}}` 미치환 |
| `check_markdown_residue` | `**굵게**` 같은 마크다운 잔여물 |
| `check_density` | 페이지 하단 25% 초과 공백 |
| `check_orphans` | 한 줄만 넘어간 고아 텍스트 |
| `check_fonts` | CJK 폰트 실제 적용 여부 |
| `check_rhythm` | 단조로운 슬라이드 시퀀스 |
| `check_resume_balance` | 이력서 좌우 균형 |

"AI의 판단"이 아니라 "코드의 판단"으로 품질을 보증하는 구조가 신뢰성의 핵심이다.

### ③ 의존성 없는 MCP 서버

외부 라이브러리 없이 표준 라이브러리만으로 MCP 서버를 구현한 실전 예제.

### ④ 우아한 성능 저하 (Graceful Degradation)

```
pygments 없음      → 코드가 흑백 (죽지 않음)
python-pptx 없음   → PDF로는 출력 (죽지 않음)
weasyprint 없음    → 명확한 에러 + 설치 명령어 안내
```

`--doctor` 로 무엇이 되고 무엇이 안 되는지 먼저 알려주는 UX도 좋은 참고 사례다.

### ⑤ Content IR (중간 표현) 패턴

디자인보다 먼저 `content.json` 으로 내용을 구조화한 뒤 템플릿에 붓는다.

- 스키마 검증 가능
- 내용 누락 자동 감지 가능
- 템플릿만 바꿔 재출력 가능

"내용과 표현의 분리"를 AI 파이프라인에 적용한 사례.

## 8. 라이선스 — 수익화 전 반드시 확인

| 항목 | 라이선스 | 상업 이용 |
|---|---|---|
| Kami 코드 · 템플릿 | **MIT** | 가능 (저작권 표시 유지) |
| **한국어 — Source Han Serif KR** | **OFL** | **가능 (무료)** |
| JetBrains Mono (코드용) | OFL | 가능 |
| Charter (영문) | 무료 배포 | 가능 |
| **중국어 — TsangerJinKai02** | **개인 사용만 무료** | **불가 — tsanger.cn 라이선스 필요** |

### 전략적 결론

> **중국어 제품** → 창저체 상업 라이선스 구매 필요 (비용 발생)
> **한국어 제품** → 폰트 비용 0원, 법적 리스크 0

저장소에 `LICENSE-SourceHanSerifK.txt` 가 동봉되어 있다. CI도 "TsangerJinKai02는
상업 폰트라 배포하지 않는다"고 명시한다. **한국 시장 타겟이 법적으로 가장 깔끔한 길이다.**

## 9. 수익화 전략

### 9-1. 진짜 팔 수 있는 자산

| 자산 | 복제 난이도 | 가치 |
|---|---|---|
| HTML 템플릿 27개 | 쉬움 (2주면 모방) | 낮음 |
| 디자인 규칙 5,200줄 | 보통 | 중간 |
| **검증 로직** | **어려움** | **높음** |
| **품질 보증 경험** | **매우 어려움** | **높음** |

템플릿은 누구나 만든다. **"결과물이 항상 일정 품질 이상으로 나오게 보증하는 시스템"**
이 팔 물건이다.

### 9-2. 포지셔닝 — 가장 중요한 판단

```
[X] "AI로 문서 만들어드려요"        → 6개월이면 범용 AI에 잠식
[O] "이 양식에 맞춰 통과되는 문서"   → 잠식되지 않음
```

차별점은 **"생성"이 아니라 "규격 준수 + 도메인 지식"** 에 두어야 한다.

### 9-3. 수익 모델 6종 비교

| # | 모델 | 초기투자 | 수익성 | 난이도 | 추천도 |
|---|---|---|---|---|---|
| 1 | 한국형 문서 SaaS | 중 | 높음 | 중 | ★★★★★ |
| 2 | 템플릿 팩 판매 | 낮음 | 낮~중 | 낮음 | ★★★★ |
| 3 | B2B 브랜드 구축 대행 | 낮음 | **매우높음** | 중 | ★★★★★ |
| 4 | 업종 특화 리포트 자동화 | 높음 | 매우높음 | 높음 | ★★★ |
| 5 | 템플릿 마켓플레이스 | 높음 | 중 | 매우높음 | ★★ |
| 6 | 콘텐츠 · 교육 (부업) | 매우낮음 | 낮음 | 낮음 | ★★★ |

### 9-4. 모델 1 — 한국형 문서 SaaS (본진)

**타겟 후보 평가**

| 타겟 | 시장크기 | 절박함 | 지불의사 | 경쟁 | 종합 |
|---|---|---|---|---|---|
| **정부지원사업 사업계획서** | 중 | 높음 | 높음 | 중 | **A+** |
| IR 덱 / 투자제안서 | 소 | 높음 | 높음 | 낮음 | A |
| 이력서 / 자소서 | 초대형 | 중 | 낮음 | 레드오션 | B |
| 연구계획서 / 학회 포스터 | 소 | 중 | 중 | 매우낮음 | B+ |

**1순위 추천: 정부지원사업 사업계획서**

- 예비창업패키지 · 초기창업패키지 · TIPS · 청년창업사관학교 등 매년 수만 명 지원
- 양식 고정 (PSST 구조: Problem - Solution - Scale up - Team)
- 분량 제한이 빡셈 → **Kami의 `check_density` 가 그대로 무기**
- 지원금이 수천만원~1억 규모 → 도구에 몇만원 지출은 부담 없음

| 킬러 기능 | Kami에서 가져오는 것 |
|---|---|
| 분량 자동 체크 ("14.2p / 15p") | `check_density` |
| 빈 항목 경고 | `check_placeholders` |
| 도표 자동 생성 (시장규모 · 로드맵) | 다이어그램 18종 |
| PSST 구조 검증 | `content.json` 스키마 |
| 심사위원 관점 셀프체크 | `anti-patterns.md` 응용 |

**가격 설계**

| 플랜 | 가격 | 내용 | 노림수 |
|---|---|---|---|
| 무료 | 0원 | 1건 / 워터마크 | 체험 유도 |
| 건별 | 19,000원 | PDF 1건 무제한 수정 | 심리적 장벽 최저 |
| 월간 | 29,000원/월 | 무제한 + 전체 템플릿 | 주력 |
| **시즌권** | **49,000원** | 3개월 | **공고 시즌(1~3월) 대응** |
| 컨설팅 결합 | 300,000원~ | 전문가 1:1 첨삭 | 고마진 |

> 정부지원사업은 공고가 시즌에 몰린다. 구독보다 **"시즌권"** 이 사용자 심리에 맞고
> 이탈률 부담도 없다.

**리스크와 방어**

| 리스크 | 방어법 |
|---|---|
| "AI가 썼다" 심사 감점 우려 | **"작성 도구"** 로 포지셔닝. 내용은 사용자, 구조·디자인만 제공 |
| HWP 제출 요구 공고 | HWP 변환 지원 또는 PDF 허용 공고 우선 타겟 |
| 시즌 편중 매출 | 비수기엔 IR덱 · 연구계획서로 타겟 확장 |
| 합격 보장 오해 | 마케팅 문구 주의 ("합격률 상승" 류 금지) |

### 9-5. 모델 3 — B2B 브랜드 템플릿 구축 (현금흐름 최고)

개발이 거의 필요 없어 가장 빨리 매출이 난다.

**납품물**

- 회사 CI(색·폰트·로고) 적용 템플릿 5~9종
- 설치 + 팀 교육
- 회사 전용 `brand.md` 프로필
- 3개월 유지보수

**고객이 돈을 내는 이유**

| 고통 | 금액 환산 |
|---|---|
| 팀원마다 제안서 디자인이 제각각 | 브랜드 훼손 |
| 디자이너가 매번 문서를 다듬음 | 인건비 낭비 |
| 외주 디자인 건당 30~100만원 | 연 수천만원 |
| 신입 제안서 품질 저하 | 수주 실패 |

**타겟**: 시리즈A 전후 스타트업 / 컨설팅·에이전시 / VC·액셀러레이터 / 산학협력단

**가격**

| 패키지 | 가격 | 범위 |
|---|---|---|
| Lite | 150만원 | 템플릿 3종 + 설치 |
| **Standard** | **400만원** | 템플릿 6종 + 교육 + 3개월 지원 |
| Pro | 800만원~ | 전체 + 사내 MCP 서버 + 1년 지원 |
| 유지보수 | 월 30만원 | 템플릿 추가 · 수정 |

> **전략**: 모델 3(대행)으로 현금을 벌면서 모델 1(SaaS)을 만든다. 대행 과정에서 얻는
> 고객 인사이트가 SaaS 기획에 그대로 쓰인다.

### 9-6. 모델 2 — 템플릿 팩 판매 (오늘 시작 가능)

| 팩 | 내용 | 가격 |
|---|---|---|
| 취업 팩 | 이력서 5종 + 자소서 + 포폴 | 29,000원 |
| 창업 팩 | 사업계획서 + IR덱 + 원페이저 | 49,000원 |
| 연구 팩 | 연구계획서 + 포스터 + 논문요약 | 39,000원 |
| 회사 팩 | 제안서 + 보고서 + 회의록 + 릴리스노트 | 59,000원 |

**채널**: Gumroad / Lemon Squeezy (해외, 수수료 낮음) · 크몽 / 탈잉 (국내) ·
자체 랜딩페이지 (Kami의 `landing-page` 템플릿으로 제작)

> 검증용으로 쓴다. 템플릿 팩이 안 팔리면 SaaS도 안 팔린다.

### 9-7. 모델 4 — 업종 특화 리포트 자동화

"양식 고정 + 데이터만 변경" 인 업종을 완전 자동화한다.

| 업종 | 문서 | 비고 |
|---|---|---|
| 증권 / 리서치 | 종목 리포트 | `equity-report` 템플릿 이미 존재 |
| 부동산 | 매물 제안서 | |
| 병원 / 검진센터 | 검진 결과 리포트 | |
| 세무 / 회계 | 결산 보고서 | |
| 마케팅 대행사 | 월간 성과 리포트 | |

```
데이터(API/엑셀/DB) → content.json 자동 생성 → Kami 렌더 → 월 수천 건 자동 발행
```

건당 500~2,000원 × 월 수천 건 = 월 수백만원 자동화 매출. 단 **도메인 지식이 필수**다.

## 10. React / PHP로 다시 만들 수 있나 → 가능

### 이식성 분석

| 구성요소 | 언어 종속성 | 이식성 |
|---|---|---|
| 템플릿 27개 | 순수 HTML + CSS | **100% 재사용** |
| 다이어그램 18종 | 순수 SVG | **100% 재사용** |
| 디자인 규칙 5,200줄 | 문서 | 그대로 사용 |
| 렌더링 엔진 | Python (WeasyPrint) | **여기만 교체** |
| 검증 스크립트 | Python | 포팅 필요 |

핵심 자산의 90%가 언어 무관이다. **"PDF 굽는 부분"만 교체**하면 된다.

### React 버전 (추천)

```
[프론트] Next.js + React
  ├─ 입력 폼 / 템플릿 선택 UI
  ├─ 실시간 미리보기 (iframe)
  └─ Tailwind

[백엔드] Next.js API Route (Node)
  ├─ Puppeteer / Playwright → page.pdf()
  ├─ pdf-lib → 페이지수 · 메타데이터
  └─ pptxgenjs → PPTX (python-pptx 대응)
```

| 장점 | 단점 |
|---|---|
| 실시간 미리보기 자연스러움 | Puppeteer가 무거움 (Chromium ~300MB) |
| Puppeteer의 CSS 지원이 WeasyPrint보다 넓음 | 서버리스는 `@sparticuz/chromium` 필요 |
| Vercel 배포 → 바로 SaaS | page-break 제어는 WeasyPrint가 더 정밀 |
| 웹폰트 처리 용이 | |

### PHP 버전 (비추천)

Laravel + Dompdf / mPDF / Snappy 조합이 가능하지만, PHP 순수 PDF 라이브러리는
CSS 지원이 약해 Kami 템플릿 수준의 정교한 레이아웃이 깨질 가능성이 높다.
결국 `Browsershot`(내부적으로 Puppeteer 호출)으로 가게 되므로, 그럴 바엔 처음부터
Node가 낫다.

### 권장 구조

```
┌─────────────────────────────┐
│  Next.js (React)            │  UI · 미리보기 · 인증 · 결제
└──────────┬──────────────────┘
           │ API
┌──────────▼──────────────────┐
│  렌더 서버 (Node + Puppeteer)│  PDF / PNG / PPTX 생성
│  ※ Kami 템플릿 · SVG 그대로  │
└─────────────────────────────┘
```

### 로드맵

| 단계 | 할 일 | 기간 |
|---|---|---|
| 1 | 템플릿 1개(resume-ko)만 Puppeteer로 PDF 출력 성공 | 1~2일 |
| 2 | 폼 입력 → 치환 → 미리보기 → 다운로드 MVP | 1주 |
| 3 | 템플릿 3~4개 확장 + 한글 폰트 임베딩 | 2주 |
| 4 | 검증 로직 포팅 (빈칸 / 여백 체크) | 1주 |
| 5 | 로그인 + 결제 + 런칭 | 2주 |

## 12. 실패 요인 3가지

| # | 실패 패턴 | 해결 |
|---|---|---|
| 1 | **템플릿만 늘리다 끝남** ("템플릿 50개!" → 아무도 안 씀) | 템플릿 3개로 시작해 **한 타겟의 문제를 끝까지** 해결. 깊이 > 넓이 |
| 2 | **"AI 문서 생성기"로 포지셔닝** (범용 AI에 잠식) | **"○○ 양식 전문"** 으로 좁힌다. 좁을수록 안전 |
| 3 | **설치 장벽을 사용자에게 전가** (`pip install` 요구 → 대량 이탈) | 웹으로 감싼다. 설치 없이 브라우저에서 완결 — **이것이 돈 받는 이유** |
